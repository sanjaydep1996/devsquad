## Pick the right kind of doc
tags: diataxis, tutorial, how-to, reference, explanation
when: doc, readme, guide, documentation
decide: Decide whether this is a tutorial, a how-to, reference or an explanation, and don't mix them in one page.

## Lead with what the reader needs
tags: readme, getting started, clarity
when: readme, guide, onboarding, getting started
decide: Open with what it is and the shortest working example; put details and edge cases after.

## Document the change with the change
tags: changelog, release notes, docs as code
when: release, feature, change, api
decide: Update the README, changelog and API reference in the same pull request as the code.

## Write plainly
tags: style, plain language
when: doc, copy, message, error
decide: Short sentences, active voice, one idea per paragraph, and examples that actually run.
